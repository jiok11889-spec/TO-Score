### 3단계 — 티어 자동 조정

> ⚠️ **기준스코어 절대 배분 방식. 대회 참가자끼리 상대 비교 금지.**

**규칙 A — T0 고정 (최우선)**
`config.py` PRO_PLAYERS 등록 선수 → 성적 무관 영구 T0. T0 원하는 비PRO도 추가 가능.

**규칙 B — 기준스코어 공식**
```
기준스코어 = 누적평균 × 0.5 + 26년평균 × 0.5
```
update_scores.py 실행 후 시트 수식이 자동 재계산. 실행 직후 아래 코드로 읽기:
```python
import urllib.request, csv, io
SHEET_ID = "16Ay7f7lhccjdfKhb-Fe1U6DVicAVq0dqS3kEzusgXg4"
url = f"https://docs.google.com/spreadsheets/d/{SHEET_ID}/export?format=csv&gid=1112772180"
req = urllib.request.Request(url, headers={"User-Agent": "Mozilla/5.0"})
with urllib.request.urlopen(req, timeout=15) as res:
    rows = list(csv.reader(io.StringIO(res.read().decode("utf-8"))))
```

**규칙 C — 동점자 처리 (D보다 선행)**
경계 타이 → 전원 상위 티어 배치. 이로 인한 인원 불균형은 규칙 D에서 흡수.

**규칙 D — 인원 배분 (기본: 각 티어 7명, 합계 35명)**
```
R = N(랭킹 대상) - 35
R > 0: T5+1, T4+1, T3+1, T2+1, T1+1, T5+1 ... 순으로 추가
R < 0: T5-1, T4-1, T3-1, T2-1, T1-1 ... 순으로 감소
```
현재 N=36 → T1=7 / T2=7 / T3=7 / T4=7 / T5=8

**규칙 E — 신규 멤버**: 첫 대회 참가 전까지 TIER_MAP 미추가. 참가 후 기준스코어 생기면 정식 배정.

**규칙 F — 탈퇴 멤버 (2026-08-04 변경)**: **시트 행과 과거 스코어는 삭제하지 말고 보존**한다(복귀 가능성). `config.py`의 `RETIRED_PLAYERS`에 이름만 추가하면 **표시·제외가 전부 자동**이다. 복귀하면 목록에서 빼기만 하면 된다.

`RETIRED_PLAYERS`에 넣으면 자동으로 적용되는 것:
- `tier_calc.py` — 티어 계산·랭킹에서 제외 (N이 줄면 규칙 D 재적용)
- `server.py` — score·matchplay·member에 `탈퇴` 플래그 부여(기록은 유지), ranking·tier_history에서 제외 후 **순위를 1부터 다시 매김**
- `dashboard.html` — 이름 옆 `탈퇴` 배지, 시즌 평균 TOP·참여 TOP 집계에서 제외

**탈퇴 처리는 `config.py` 한 곳만 고칠 것.** 시트에서 행을 지우거나 이름을 바꾸지 말 것 — 그렇게 하면 과거 기록이 끊기고 배열수식이 깨진다.

**티어 계산 도구** — 손으로 계산하지 말고 이걸 쓸 것:
```
python tier_calc.py            # 계산 + 현재 티어와 비교 (쓰기 없음)
python tier_calc.py --write    # 시트의 '현재 티어' 열만 갱신 (행 삭제·열 삽입 없음)
python tier_calc.py --emit     # update_scores.py에 붙일 TIER_MAP 블록 출력
```
유지 멤버(탈퇴·PRO·기준스코어 없음 제외)만으로 규칙 C→D를 적용한다. 멱등이라 재실행해도 안전하고, 변동 인원을 먼저 보여주므로 `--write` 전에 반드시 눈으로 확인할 것.

**⚠️ `update_scores.py`를 티어 반영 목적으로 재실행하지 말 것** — `update_tier_history_sheet()`가 티어정리 시트에 **회차 열을 새로 삽입**하므로 중복 열이 생긴다. 대회 없는 재배분은 `tier_calc.py --write`만 쓸 것.

**티어 이력 기록도 잊지 말 것**: `tier_calc.py --write`는 `스코어 집계`의 '현재 티어' 열만 고친다. `티어정리_신규` 시트의 다음 **회차 열에 직접** 새 티어를 써 넣어야 대시보드의 "최근 대회 티어 변동" 패널이 최신 결과를 보여준다. 안 그러면 화면이 **직전 대회 비교를 계속 표시**해 공지 내용과 어긋난다(2026-08-04 실제 혼선). 대회가 아닌 재배분이면 **날짜 칸은 비워 둔다** — 채우면 '최근 대회 날짜'가 그 날로 잘못 잡힌다.

## 티어 변동 공지 절차

1. **모든 데이터 정정·검증을 끝낸 뒤에** 공지안을 만든다. 작업 중간에 초안을 주면 이후 정정으로 틀린 공지가 나간다 ([[announce-only-when-final]] — 2026-08-04 실제 사고)
2. 변동 비교 기준은 git 커밋이나 시트가 아니라 **사용자가 마지막으로 단톡방에 공지한 내용**이다. 먼저 그것부터 확인할 것
3. 이미 나간 공지가 틀렸으면 정정 공지안을 낸다. 공지문엔 **사유와 양해 요청만** 담고 과도한 사과는 넣지 않는다(사과는 사용자에게 직접)
4. 공지 전 `python tier_calc.py`로 변동 0건인지, `python audit_scores.py`로 정합성 0건인지 확인
5. **공지안에 대시보드 링크를 반드시 포함**: https://to-score.onrender.com (2026-09-12 사용자 지시). 시트를 실시간으로 읽으므로 push 없이도 새 결과가 보인다

**대회 미참가자도 기준스코어가 바뀌면 재배정 대상.**

**조정 절차**:

2. **직전 월 지출 내역** (건별): 날짜 / 금액 / 분류 / 비고
3. **직전 월 이자**: 금액
4. **당월 회비 입금자 명단**
5. **현재 통장 잔액** (검증용)

계좌: 카카오뱅크 3333-33-8606723 (예금주: 옥지엽, 본인 명의 계좌라 CSV 확보 가능)
카카오뱅크 CSV는 비밀번호로 암호화된 xlsx(OLE2 포맷)로 제공됨 — `msoffcrypto` 라이브러리로 복호화 필요:
```python
import msoffcrypto, io, openpyxl
with open(경로, 'rb') as f:
    office_file = msoffcrypto.OfficeFile(f)
    office_file.load_key(password=비밀번호)  # 사용자에게 요청
    decrypted = io.BytesIO()
    office_file.decrypt(decrypted)
wb = openpyxl.load_workbook(decrypted, data_only=True)
```
비밀번호는 매번 사용자에게 확인.

**신규 멤버 회비 납부 시작 규칙**: N월에 신규 가입 → 회비는 **N+1월 1일부터** 납부 시작 (가입월은 면제).
예) 6월 가입 → 6월 컬럼 공란, 7월부터 20000 시작. 5월 가입 → 5월 공란, 6월부터 시작.

**선납 처리 (2026-08-04 확립)**: 회비 배수로 한 번에 넣으면 선납이다(예: 100,000 = 5개월치, 120,000 = 6개월치).
- **첫 미납월부터 연속으로** 각 월 컬럼에 회비 금액씩 채운다. 받은 달에 몰아넣지 않는다
- 연도를 넘어가면(예: 27년 1월) **원장에 그 달 회비 SUMIFS 행을 새로 append**해야 집계된다. 행 삽입이 아니라 맨 끝에 추가 — 기존 행이 안 밀린다
- 잔액은 `load_income_by_month()`가 입금현황을 직접 합산하므로 미래 월에 넣어도 정확히 반영된다
- **선납 후 반드시 확인할 부작용 2가지** (2026-08-04에 둘 다 발생):
  1. 대시보드 최신월이 미래로 밀려 기본 화면이 엉뚱한 달을 보여준다 → `load_all_payment_status`에서 현재 달까지로 제한 (수정 완료)
  2. 월평균 입금 통계가 미래 달의 소액 때문에 폭락한다 → 평균 집계에서 미래 월 제외 (수정 완료)
  코드는 고쳐뒀지만, 선납이 생기면 **대시보드에서 최신월·월평균이 상식적인지 눈으로 확인할 것**

**중복입금(미환급)**: 실제 받은 금액을 그대로 기입해 잔액을 맞춘다(예: 40,000). 환급 송금 시점에 원장에 출금 항목을 추가하고 해당 월을 정상 회비로 되돌린다.

**미납 처리 원칙 (2026-08-03 변경)**: 매 정산마다 **전월 이전 누적 미납분까지 체크**해서 보고한다. 이전 월 행까지 훑어 **인원별 미납 개월수와 누적 미납액**을 산출할 것 — 당월만 보면 몇 달째 밀린 사람과 이번 달만 안 낸 사람이 구분되지 않는다.
- 다만 **사용자에게 캐묻지는 말 것**. 은행 CSV·시트에서 확인되는 사실로 산출해서 보고만 하면 된다. (기존 "전월 미납은 해소된 것으로 간주" 규칙은 폐기)
- 부분납부(회비 일부만 입금)는 완납과 구분해 "부분납부 N원 / 잔여 M원"으로 표기한다.

**잔액 검증 습관**: 은행 CSV 확보 시, 반영 전에 거래 전후 잔액이 각 행마다 정확히 맞아떨어지는지(자기 정합성) 먼저 검증. 이 방식이 신뢰도를 높인다고 확인받음(2026-07-01).

**캡처가 잘려 있으면 반드시 추가 캡처를 요청할 것.** 거래내역 이미지 하단이 끊긴 채로 나머지를 추론해서 메우면 안 된다.

**질문은 한 번에 모아서** 한다. 위 5가지를 여러 턴에 쪼개 묻지 말고, 입력이 다 모이기 전에는 엑셀 작업에 착수하지 않는다.

## 동명이인 표기 규칙 (2026-08-04 확립)

**동명이인은 전원 출생연도를 괄호로 붙여 구분한다.** 한쪽만 괄호를 쓰면 다른 쪽이 "기본값"이 되어 오염이 생긴다.

- 현재: `김성환(82)` / `김성환(92)` — 이전엔 `김성환` / `김성환(92)`였다
- 새 동명이인이 생기면 **양쪽 다** 연도를 붙일 것

**실제 사고(2026-08-04 발견)**: 26년 3월 22일 스코어카드 원본에 두 김성환을 구분하는 표기가 없었고, `김성환* = 92` 규칙은 7/19 5차 대회에서야 도입됐다. 그 사이 4/5에 3/22 스코어를 전사하면서 100점이 기본 행(김성환)으로 들어가 **4개월간 잘못된 티어·통계가 노출**됐고 본인 컴플레인으로 발견됐다.

**대회 스코어 전사 시 필수**: 스코어카드에 동명이인이 있으면 **누구인지 먼저 확인**하고 전사할 것. 카드에 구분 표기가 없으면 참가자에게 확인. 추측 금지.

**정합성 검증**: `python audit_scores.py` — 표시 통계와 실제 스코어 계산값을 대조한다. `--fix`는 통계 수식 범위를 교정한다. **대회 반영 후 반드시 0건인지 확인할 것.**

## ⚠️ 배열수식 자리에 이름을 직접 타이핑하지 말 것 (2026-08-04 사고)

스코어 대시보드가 읽는 시트 중 셋은 이름 목록을 **배열수식으로 끌어온다**. 그 확산 범위에 값을 손으로 넣으면 `#REF!`가 되고 시트 전체가 죽는다.

| 시트 | 셀 | 수식 |
|---|---|---|
| 멤버명단 (자동) | B3 | `=SORT(UNIQUE('스코어 집계 (입력)'!B5:B),1,TRUE)` |
| 티어정리_신규 | B10 | `=ARRAYFORMULA('스코어 집계 (입력)'!B5:B)` |
| 매치플레이 전용 | B4 | `=FILTER('스코어 집계 (입력)'!B5:B, ...!AD5:AD>=1)` |

실제 피해: 멤버 탭이 43명 → 6건으로 깨진 채 방치돼 있었다. **멤버를 추가할 땐 `스코어 집계 (입력)` 시트에만 넣으면 나머지는 자동으로 따라온다.** 다른 시트에 손으로 넣지 말 것.

증상 점검: `python -c "import server; d=server.get_all_data(); print({k: len(v) for k,v in d.items() if isinstance(v,list)})"` — member가 43 근처가 아니면 막힌 것이다.

## 매치플레이 결과 입력 방법 (2026-08-04 재구성)

**`매치플레이 입력` 시트에 한 줄씩 적는다.** 절대 `매치플레이 전용` 시트에 직접 타이핑하지 말 것.

| 대회명 | 이름 | 결과 | 날짜 | 비고 |
|---|---|---|---|---|
| 25' 매치플레이 4차 | 조현민 | WIN | 11/1/2026 | |

- **대회명은 `매치플레이 전용` 시트 2행의 대회명과 정확히 같아야** 집계된다
- 결과는 `WIN` / `LOST` / `DRAW`. **불참자는 아예 적지 않는다**
- `매치플레이 전용` 시트의 승패·승리·승률은 **이름으로 조회**하므로 행 순서가 바뀌거나 멤버가 빠져도 안 깨진다

**왜 이렇게 바꿨나**: 원래는 이름이 배열수식(자동), 승패가 수기(수동)라 **"같은 행"이라는 것 말고 연결고리가 없었다.** 배열이 깨지고 탈퇴자 행이 삭제되자 승패 17행이 주인을 잃었고, 개인별 귀속이 영구 불능이 됐다(조현민 3전 전승만 패턴상 확정). 그 17행은 `매치플레이 입력` 시트 하단에 "이름 미상"으로 보관해 뒀다.

**주의**: 매치플레이 명단은 `스코어 집계` 기준이라 **탈퇴자도 포함된다**(과거 참가 기록이므로 의도적). 현재 김수민(탈퇴)이 들어 있다.

**25년 대회 데이터는 원본 대조 없이 그대로 쓴다 (2026-08-04 결정)**: 25년 11개 대회 열은 스코어카드 원본이 남아있지 않아 검증 수단이 없다. 이상 징후도 없으므로 **재검토 대상이 아니다**. 누적평균을 통해 현재 티어에 계속 반영된다는 점만 알아둘 것. 원본이 있는 구간(26년 1차 이후)은 전부 대조 완료됐다.

**동명이인 입금 처리**: 은행 거래내역엔 이름만 찍혀서 여러 동명이인 중 누구 건인지 구분 불가.
- 해당 이름 입금 **건수 = 동명이인 인원수** → 전원 납부 처리 (문제없음)
- 건수 = 0 → 전원 미납 (문제없음)
- **건수가 인원수보다 적을 때(예: 2명 중 1명만 입금)** → 누구 건인지 임의 배정 금지, 반드시 사용자에게 확인. 이게 실제로 위험한 유일한 케이스.

**작업 기준**
- 매월 초 작업, 직전 월말까지 지출·이자 반영
- 작업 당일 입금 회비 → 당월 처리 (직전 월 아님)

### 작업 순서

**1. 원장 시트**: 지출·이자 행 추가 (날짜/분류/금액). 회비 행은 수식 자동계산.

**2. 입금현황 시트**

- 값 입력 후 노란 음영 제거 (인접 완료 셀 서식 복사)

**3. 회비입출내역 시트**: 해당 월 잔액 기준일·금액 업데이트(I16/J16 셀) → TRUE 확인
- "전월"(C1)·"당월"(F1) 헤더는 `참고` 시트의 `TODAY()` 기반 수식이라 **매번 열 때마다 자동으로 최신 월로 이동**함 (수동 수정 불필요). 현재 로직상 "당월"=실제 달력의 전월, "전월"=전전월로 한 달씩 밀려 있음 — 매월 초에 직전 월을 정산하는 작업 방식과 맞물려 있는 설계이므로 그대로 둘 것.

### 오입금 처리 (사용자 확인 필수)

회비 금액보다 **많이** 들어온 건이 있으면 임의로 처리하지 말고, 정산 보고에 **인별 표**로 올려 사용자에게 환불 여부를 물을 것.

| 이름 | 입금액 | 회비 | 오입금액 | 발생 월 |
|---|---|---|---|---|

**왜 물어보는가**: 카카오뱅크로 환불 송금하면 수취인이 **24시간 안에 수락**해야 완료된다. 안 받으면 반송돼서 다시 보내야 하므로 번거롭다. 기본값은 환불이 아니라 **선입금 처리**.

**사용자에게 전달할 안내 문구 형태**:

## 데이터 정확성 (2026-08-03 사군자 오기입 사고 재발방지)

**납부자 이름을 추정해서 채워 넣지 말 것.** 금액 갭이 생겼을 때 "이 사람이 냈겠지" 하고 이름을 넣는 것은 없는 사실을 만들어내는 것이다.
- 실제 사고: 사군자 정산에서 20만원 갭을 메우려 두 명을 임의로 납부자로 기입 → 실제로는 둘 다 미납, 진짜 납부자는 다른 사람이었음
- **합계 일치는 개인별 정확성의 증거가 아니다.** 총액이 맞아도 누가 냈는지는 틀릴 수 있다
- 미확인분은 "미확인" 상태로 두고 사용자에게 원본을 요청할 것 (동명이인 규칙과 같은 원리)

**사람 이름이 걸린 판단은 추론 전에 원본을 조회할 것.** 입금현황 시트를 직접 읽으면 즉시 나오는 답을 추론으로 돌아가며 시간 낭비하지 말 것.

**검증은 최소 충분하게**: 통장 실잔액이 진실의 원천. 교차검증을 겹겹이 설계하지 말고 최종 잔액 대조로 끝낼 것.

## 기술 주의사항

**한글 출력은 UTF-8 래퍼 필수** — 이 환경(Windows, cp949)에서 파이썬 한글 출력 시 깨진다:
```python
import sys, io
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding="utf-8")
```

**엑셀 컬럼을 추측하지 말 것** — 헤더 행을 먼저 덤프해 컬럼 인덱스를 확정한 뒤 코드를 쓸 것. 추측한 컬럼으로 계산하면 0원 같은 무의미한 결과가 나와 검증 자체가 헛돈다.

**이미 검증된 계산이 있으면 재계산하지 말 것** — 대시보드 `/api/data`가 잔액·집계를 이미 계산한다.

## 수식 셀 규칙 (핵심)

- 수식이 걸린 셀에 값 덮어쓰기 **절대 금지**
- 잔액 불일치 시 억지로 맞추지 말고 차액·원인 그대로 보고
- 지출 계산: `net = r['차변'] - (r['대변'] if r['대변'] else 0)` (음수 대변도 반영) — **finance/src/dashboard.py는 아직 이 수정 미반영, 발견 시 사군자와 동일하게 고칠 것**

**⚠️ openpyxl `insert_rows()` / `delete_rows()` 사용 시 필수 확인 (2026-07-01 사고)**
둘 다 기존 행들을 물리적으로 밀지만(삽입=아래로, 삭제=위로):
1. **수식 안의 셀 참조 텍스트를 자동으로 안 바꿔준다** (Excel 자체 행 삽입/삭제와 다름). 예: 8행에 있던 `=RIGHT(YEAR(C8),2)...`가 14행으로 밀려도 여전히 `C8`을 참조 — 밀린 모든 행의 수식을 **자기 행 번호로 수동 재작성** 필수. `delete_rows()`도 똑같이 깨짐(반대 방향으로 한 칸씩).
2. **서식(날짜/숫자 표시형식, 폰트, 테두리)도 안 따라온다** — 새로 삽입된 행은 인접 정상 행에서 `copy.copy()`로 서식 복사 필수.
삽입/삭제 후 반드시 전체 범위(밀린 행 전부)의 수식·서식을 다시 읽어서 확인할 것. 다른 시트가 `원장`을 전체열 참조(`원장!$A:$A` 등)로 걸어뒀으면 그쪽은 영향 없음 — 문제는 원장 자체 내부의 행 번호 하드코딩된 수식뿐.

**은행내역 기반 지출 추가 시 중복 체크 필수**: 기존 원장에 이미 비슷한 금액·같은 사람 이름의 항목이 있는지 먼저 대조할 것. 기존 항목의 날짜가 부정확(추정치)할 수 있어서, 은행내역에 새로 나타난 거래가 사실은 이미 기록된 항목과 동일 거래일 수 있음(2026-07-01: "황인호, 현수막 제작 94,300원"이 5/17로 잘못 기재돼 있었는데 실제로는 6/1 거래와 동일 건 — 중복 입력해서 잔액이 94,300원만큼 안 맞았음). 은행내역 대조 후 잔액이 딱 안 맞으면 최우선으로 중복 입력을 의심할 것.

**미환급 중복입금 임시 처리**: 회원이 실수로 두 번 입금하고 아직 환급 전이면, 입금현황엔 실제 받은 금액 그대로(예: 40,000원) 기입 — 대시보드 잔액이 실제 통장과 항상 일치하도록. 나중에 실제 환급 송금하면 그 시점에 원장에 출금 항목 추가 + 입금현황 금액을 원래 회비(20,000원)로 되돌림.
